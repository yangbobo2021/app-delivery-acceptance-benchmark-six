# Python CLI 覆盖率准备

在每次验收先重新建立并验证 Python 运行环境，再选用项目测试目录的 `coverage_support` 适配器。当前适配器使用 coverage.py 7.16.2 的公开 CoverageData API 合并原生数据，独立读取脚本使用 coverage.py 官方 CLI 对同一份只读快照生成 JSON 报告。工具负责行与分支单位、零命中分母及统计；适配器只调用工具、绑定证据、规范化路径与报告。

基线 be95265 的 AT-20261020-v1-python 首次覆盖率尝试在两路零命中探针出现 `KeyError: 'covered_branches'`，非零探针通过。原因是全空 arc 表经合并后丢失分支模式。第二次尝试采集测试适配器自身的真实执行，以保留分支模式，再由工具对显式产品源码文件出报告；没有插入虚构 arc 或命中。两条路由的零/非零命中探针及独立读取均通过。具体原始报告保存在该次验收的本机工作流内，不作为新验收凭据。

新验收应按本次运行环境重新核对工具版本和安装摘要，验证最终 `verify-preparation` 入口，并重新执行零/非零探针。未启动、原生快照缺失或收尾不完整必须报告 incomplete/unavailable，不能使用零命中基线冒充采集。真实业务用例的 `run → finish → verify-report → summarize` 仍须在该用例正式执行时逐次验证；非业务探针不提供业务覆盖率。
